# Alert Component

Alert components provide contextual feedback messages for user actions: a lightly tinted box with a coloured icon and dark, readable text.

## Available Classes

### Container

- `.alert-wrapper` - Wrapper container with responsive padding (1rem on mobile, 2.5rem horizontal on 40em+)

### Base Alert

- `.alert` - Base alert: tinted background, thin border and rounded corners. Without a type it is neutral and has no icon

### Alert Types

- `.alert-success` - Green tint with a check-in-circle icon
- `.alert-info` - Blue tint with an "i" icon
- `.alert-warning` - Amber tint with a "!" icon
- `.alert-danger` - Red tint with a cross-in-circle icon

### Content

An alert can hold plain text, or a title and a description:

- `.alert-title` - Medium-weight first line in the heading colour
- `.alert-description` - Supporting text in the body colour

## Features

### Built-in Icons

Each alert type draws its icon in CSS: a circle outline on `::before` and a mark on `::after`, both in the type's colour. No images are used, so the icons are not blocked by an `img-src` Content-Security-Policy, such as the Identity Server's:

- **Success**: Check in a circle
- **Info**: "i" in a circle
- **Warning**: Exclamation mark in a circle
- **Danger**: Cross in a circle

### Responsive Design

The alert wrapper automatically adjusts padding:
- Mobile: 1rem padding on all sides
- Desktop (40em+): 2.5rem horizontal padding

### Semantic Colors

Uses CSS custom properties for consistent theming:
- `--color-success` - Green for success
- `--color-info` - Blue for information
- `--color-warning` - Amber for warnings
- `--color-danger` - Red for errors

The background and border are mixed from the type colour, so changing a colour token
restyles the whole alert.

## Dark Mode Support

Alerts automatically adapt to dark mode when used within `.body-dark .form-transparent` contexts: the tint becomes translucent and the text white.

## Styling Details

- **Min-width**: 30em, or the full width when the container is narrower
- **Max-width**: 100%
- **Border radius**: 8px (configurable via `--alert-border-radius`)
- **Font size**: 0.875rem
- **Icon size**: 1.25rem (configurable via `--alert-icon-size`)

## Best Practices

1. **Use semantic types**: Choose the alert type that matches the message context
   - Success: Confirmations, successful operations
   - Info: Helpful information, tips
   - Warning: Cautions, important notices
   - Danger: Errors, critical issues

2. **Keep messages concise**: Alert text should be brief and actionable

3. **Use wrapper for multiple alerts**: When displaying multiple alerts, wrap them in `.alert-wrapper` for consistent spacing

4. **Position wisely**: Place alerts near the relevant content or at the top of forms

5. **Consider dismissibility**: For non-critical alerts, consider adding a close button

## Accessibility

- Alerts use semantic colors with sufficient contrast
- Icons provide visual reinforcement of message type
- Text uses the heading colour on a light tint, so it stays readable whatever the type colour
- Works with screen readers (consider adding `role="alert"` for dynamic alerts)
